# Offline vision integration — implementation notes

## Verified repository state (2026-11-12)

- Expo SDK 54 / React Native 0.81.5 app.
- Existing local face flow is in `lib/faceRecognition.ts`.
- The app bundles `assets/models/mobile_face_net.tflite` and `assets/models/mobile_facenet.tflite`; the code explicitly loads the former and expects a 112x112 RGB input with a 192-dimensional embedding.
- Face crops and embeddings are generated by the installed Nitro ML Kit packages.
- Enrollment and recognition are performed in the app process. Face profiles are AES-encrypted in AsyncStorage; the AES key is held in SecureStore with device-only keychain accessibility.
- The camera screen routes identity questions to `answerLocalFaceCommand`; other visual questions currently use the remote vision API.
- No on-device object-detection runtime or compatible object-detection model is currently wired into the app.

## Privacy boundary

The local face-identity path must remain local: no face images, face embeddings, names, or relationship labels may be sent to the backend. Keep the app's local face gallery separate from server-side face endpoints. Do not describe the entire vision experience as offline while general scene Q&A still calls the backend.

## Face-recognition requirements before release

1. Confirm the exact model file's license, source, input normalization, output dimension, and model checksum. Do not swap the model based only on its filename.
2. Validate model initialization on physical iOS and Android devices.
3. Add quality gates for face size, blur, pose, illumination, and occlusion during enrollment and matching.
4. Store multiple normalized embeddings per person (not only a single average) so pose variation can be represented; use a calibrated threshold and ambiguity margin measured on a representative validation set.
5. Treat long-distance recognition as unsupported unless measured at the intended camera resolution and distance. No face model can guarantee identity from a face with too few pixels.
6. Verify profile encryption, key-loss behavior, deletion, and offline operation with network disabled.

## Object detection / pose requirements

1. Choose a mobile runtime compatible with Expo SDK 54 and the project's native build workflow.
2. Supply a legally usable mobile model (TFLite/Core ML/ONNX as supported by the selected runtime), not the server-side Ultralytics `.pt` checkpoint.
3. Benchmark latency, memory, thermal behavior, and detection quality on the target phone.
4. Add object labels, confidence, normalized bounding boxes, tracking, and optional pose keypoints.
5. Run inference on-device and keep frames off the network for the offline detection mode.
6. Distinguish object detection from face identification: pose estimation can describe body posture, but it must not be used to infer a person's identity or sensitive traits.

## Current status

Development branch created. Existing face-recognition implementation inspected. Object detection is not yet implemented or tested in this mobile app. No claim of end-to-end offline operation should be made until a compatible model/runtime is added and physical-device tests pass.
